## 5. Установка и запуск

Все команды выполняются из каталога `laboratory_work_2`.

### 5.1. Создание виртуального окружения

Требуется Python 3.10.

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 5.2. Установка зависимостей

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 5.3. Настройка окружения

Создайте локальный файл конфигурации:

```powershell
Copy-Item .env.example .env
```

Укажите в `.env` параметры подключения к PostgreSQL и собственный секретный ключ Django.

Сгенерировать секретный ключ:

```powershell
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Локальный `.env` не должен попадать в Git.

### 5.4. Запуск PostgreSQL

Запустите Docker Desktop, затем выполните:

```powershell
docker compose up -d postgres
```

Проверка состояния контейнера:

```powershell
docker compose ps
```

Для остановки:

```powershell
docker compose down
```

Именованный Docker volume сохраняет данные после остановки или удаления контейнера командой `down`.

### 5.5. Применение миграций

```powershell
python manage.py makemigrations
python manage.py migrate
```

Просмотр состояния миграций:

```powershell
python manage.py showmigrations
```

### 5.6. Проверка PostgreSQL

```powershell
python manage.py shell -c "from django.db import connection; connection.ensure_connection(); print(connection.vendor)"
```

Ожидаемый результат:

```text
postgresql
```

### 5.7. Запуск Django

```powershell
python manage.py check
python manage.py runserver
```

Адрес приложения:

http://127.0.0.1:8000/

Административная панель будет доступна по адресу:

http://127.0.0.1:8000/admin/

Для входа в административную панель после настройки моделей необходимо создать суперпользователя:

```powershell
python manage.py createsuperuser
```

### 5.8. Пользовательский интерфейс

После запуска сервера доступны:

- `/` — главная страница с перенаправлением на табло.
- `/flights/` — список авиарейсов.
- `/flights/<id>/` — подробная информация о рейсе.
- `/accounts/register/` — регистрация.
- `/accounts/login/` — вход.
- `/cars/` и `/owners/` — страницы практических заданий.

Основное приложение авиарейсов использует шаблонизатор Jinja2.

## 6. Архитектура

Проект использует архитектуру Django MVT (Model — View — Template).

- **Model** — определяет структуру данных и взаимодействует с PostgreSQL посредством Django ORM.
- **View** — обрабатывает HTTP-запросы и управляет логикой приложения.
- **Template** — формирует HTML-страницы на основе переданных данных.
- **URL dispatcher** — связывает URL-адреса с представлениями.

Для управления схемой базы данных используется механизм миграций Django.

Модель пользователя основана на `AbstractUser`, что позволяет расширять стандартные поля пользователя без замены механизма аутентификации.
