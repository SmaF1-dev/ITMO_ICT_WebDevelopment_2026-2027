## Цель

Освоить разработку серверных веб-приложений на Django 3: ORM, модели данных и миграции, формы, FBV/CBV, маршрутизацию, шаблоны, Django Admin, регистрацию пользователей и разграничение прав. Реализовать индивидуальный сервис табло авиарейсов с бронированием мест, регистрацией пассажиров и отзывами.

## Состав работы

### Практика 2.1 — модели и Django Admin

- `CarOwner` — владелец автомобиля; `Car` — автомобиль; `DriverLicense` — водительское удостоверение.
- `Ownership` — история владения автомобилем с датами начала и окончания.
- Связи `OneToOne`, `ForeignKey`, `ManyToMany` через промежуточную таблицу.
- Проверка сроков действия водительского удостоверения и отсутствия пересечений периодов владения одним автомобилем.
- Регистрация моделей в Django Admin, демонстрационные записи, страница владельца по ID.

### Практика 2.2 — формы и CRUD

- Списки и карточки владельцев и автомобилей через FBV/CBV.
- Создание владельцев и CRUD автомобилей (`Create`, `Read`, `Update`, `Delete`).
- Валидация форм и разграничение доступа к изменяющим операциям.

### Практика 2.3 — модель пользователя

- Собственный `accounts.User`, наследующий `AbstractUser`.
- Дополнительные поля: номер паспорта, домашний адрес, национальность.
- Связь пользовательской записи и профиля владельца автомобиля (`CarOwner`).
- Создание пользователя со связанным профилем через Django-форму.

### Индивидуальный вариант №3 — FlightBoard

- Табло прибытий и отправлений: номер рейса, авиакомпания, аэропорты, время, выход, количество свободных мест.
- Поиск по номеру рейса, авиакомпании и аэропортам; фильтры, сортировка и пагинация.
- Регистрация пользователей, вход и выход из аккаунта.
- Бронирование свободного места, изменение или отмена собственного бронирования до регистрации пассажира.
- Отзывы об уже завершённых рейсах, оценка от 1 до 10, вычисление средней оценки, редактирование и удаление своего отзыва.
- Рабочее место сотрудника (`is_staff`): поиск бронирований, назначение уникального номера билета, регистрация пассажиров.
- Публичный список пассажиров и статусов по рейсу без публикации номеров билетов.
- Адаптивная вёрстка для мобильных и настольных экранов.

## Запуск проекта

Все команды выполняются из каталога `students/K3340/Lyutyi_Nikita/laboratory_work_2` на Windows PowerShell. Нужны Python 3.10 и Docker Desktop.

### 1. Виртуальное окружение

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию, можно использовать `.\.venv\Scripts\python.exe` вместо `python`, не меняя политику выполнения скриптов.

### 2. Конфигурация PostgreSQL

```powershell
Copy-Item .env.example .env
```

Заполните переменные БД и `SECRET_KEY` в `.env` по примеру. В `compose.yaml` используется PostgreSQL с внешним портом **5433** и отдельным Docker volume. Не добавляйте `.env`, виртуальное окружение и данные PostgreSQL в Git.

```powershell
docker compose up -d postgres
docker compose ps
```

### 3. Миграции и запуск

```powershell
python manage.py migrate
python manage.py check
python manage.py createsuperuser
python manage.py runserver
```

Приложение: <http://127.0.0.1:8000/flights/>  
Администрирование: <http://127.0.0.1:8000/admin/>

Команда `createsuperuser` нужна только для новой БД; если администратор уже создан, повторять не нужно.

### 4. Демонстрационные данные (по желанию, для чистой БД)

```powershell
python manage.py loaddata project_first_app/fixtures/practice_demo.json
python manage.py loaddata flights/fixtures/demo_flights.json
```

Фикстуры содержат демонстрационные данные предметных областей. Пользователи и бронирования, созданные вручную, не являются обязательной частью фикстуры авиарейсов. На заполненной БД повторно загружать фикстуры не требуется.

## Правила доступа и целостность данных

- Гость может смотреть рейсы, публичные списки пассажиров и отзывы.
- Авторизованный пользователь может управлять только своими незарегистрированными бронированиями и собственными отзывами.
- Сотрудник (`is_staff`) может регистрировать пассажиров и назначать билеты.
- После регистрации пассажир не может самостоятельно изменить или отменить бронь.
- Ограничения уникальности места, номера билета и отзыва дополнительно проверяются на уровне PostgreSQL.
- Состояния бронирования обновляются атомарно в транзакции.
